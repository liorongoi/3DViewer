# Production readiness

**Standing direction from the product owner, 7 Nov 2026:** the product ships as a production system, not a proof of concept or a staging build. This file lists every gap found against that bar and how each one was closed. A gap stays on the list, marked open, until the fix is merged with a test or check that would catch it coming back.

Review of 7 Nov 2026, over the server, the web app, the deployment files and CI.

| # | Area | Gap | Severity | Fix | Status |
|---|---|---|---|---|---|
| 1 | Config | The server reads its settings with no checks: a typo such as `PORT=80a` or `JOB_LEASE_SECONDS=abc` starts it with `NaN`. Without `DATABASE_URL` it quietly uses the embedded database, and it seeds the sample library unless `SEED_SAMPLES=0`. | High | Every setting is parsed and checked at start, and a wrong one stops the server with a message naming it. In production (`NODE_ENV=production`) `DATABASE_URL` is required, and samples are off unless asked for. | Fixed: `apps/server/src/config.ts`, exit code 78; tests `config.test.ts`, `process.e2e.test.ts` |
| 2 | Operations | `/api/health` answers "ok" without touching the database or the storage folder, so a load balancer or monitor sees a broken server as healthy. | High | `/api/health` checks the database and that storage can be written, and answers 503 naming what failed. `/api/health/live` only says the process answers. | Fixed: tests `health.test.ts`, `process.e2e.test.ts` |
| 3 | Reliability | An unhandled promise rejection or exception is not logged or acted on, and shutdown can hang forever on a stuck job. | High | Both are logged and the process exits, so the service manager restarts it. Shutdown has a 30 s limit. | Fixed: `main.ts`; clean SIGTERM tested in `process.e2e.test.ts` |
| 4 | Web app | A rendering error in any panel blanks the whole app with no message. | High | An error boundary keeps the 3D view and shows what failed, with Reload. | Fixed: `Guard` around each part of the interface, with Try again and Reload; check `scripts/check-faults.cjs` |
| 5 | Localisation | Many labels and messages are written in English in the code, so the Hebrew interface shows English text in places (performance panel, side panels, upload steps, LOD inspector and others). | High | Every user-facing string goes through i18next with English and Hebrew. A check in CI fails the build on any new string written straight into the interface. | Open |
| 6 | Deployment | No service definitions, no single settings reference, and no backup, restore or upgrade procedure. | High | systemd units for the server and Caddy, an environment file template, `backup` and `restore` scripts (database dump and model files) with a restore test, and an operations guide. | Open |
| 7 | CI | The browser acceptance checks (shell, layers and the rest) run only by hand. | Medium | A browser job in CI builds the app and runs the shell and layers checks on every pull request. | Open |
| 8 | Security | The public write endpoints (model edits, layer arrangement, uploads) have no rate limit, so one workstation running a faulty script can flood the server and the audit log. | Medium | A per-address limit on write requests, answered with 429 and a Retry-After header. Its size is configurable. | Fixed: `WRITE_RATE_LIMIT` (600 a minute by default; upload chunks do not count); test `rate-limit.test.ts` |
| 9 | Reliability | Database calls have no time limit, so one stuck query can hold a connection forever. | Medium | Statement and idle-transaction timeouts on every connection, and a connection-wait limit on the pool. | Fixed: statement limit 60 s (`DB_STATEMENT_TIMEOUT_MS`), idle transaction 5 min, connection wait 10 s; test `db-timeout.test.ts` on PostgreSQL in CI |
| 10 | Licences | There is no generated list of third-party licences to ship with the product. | Medium | A script writes `THIRD_PARTY_LICENSES.md` from the installed packages, and CI fails on a licence outside the allowed list. | Open |

Already in place before this review, so not listed as gaps: TLS-only front end with HSTS and the other security headers (`deploy/caddy`); CSP in the web app; argon2id admin password with lockout; unpack guards for zip slip and zip bombs; a hash-chained audit log that the database refuses to change; job leases, so a crashed worker's job is taken up again; contract tests on every API answer; tests on embedded and real PostgreSQL in CI.
